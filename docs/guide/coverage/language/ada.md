# Ada / SPARK

Trivy inventories projects managed by [ALIRE](https://alire.ada.dev/), using
`alire.toml` and the generated `alire/alire.lock` resolution file.

| Package manager | SBOM | Vulnerability | License |
|-----------------|:----:|:-------------:|:-------:|
| ALIRE           | ✓    | -             | ✓       |

ALIRE inventory is enabled for filesystem and repository targets. It is disabled
for image and rootfs targets. Ada source imports, GPR files, compiler caches, and
compiled Ada binaries are not analyzed for dependencies.

## Generate an SBOM

```sh
trivy fs --format cyclonedx --output alire.cdx.json /path/to/project
trivy fs --format spdx-json --output alire.spdx.json /path/to/project
trivy repo --format cyclonedx --output alire.cdx.json /path/to/repository
```

The scanner pairs each `project/alire/alire.lock` only with
`project/alire.toml`, including in nested projects. It reads the files already
present in the scanned artifact. It does not run `alr`, resolve dependencies,
download an index, read host caches, install compilers, or execute project actions.
Generated/deployed projects inside ALIRE's `cache`, `builds`, `releases`, and
`tmp` directories are excluded.

## Supported evidence

The initial supported layout is generated by **ALIRE 2.1.1**. Legacy root-level
`alire.lock` and the name `alire.loc` are not recognized. ALIRE treats its
lockfile as internal generated state, so other layouts require validation.

For supported complete resolutions, the inventory includes:

- The root crate name, version, and available license expression from its manifest.
- Selected direct and transitive releases and their license expressions.
- Actual dependency edges, including shared dependencies, in CycloneDX and SPDX.
- Version pins and relative local overrides with manifests available inside the
  scanned artifact. Local overrides can have `pinned=false` and ignore the
  declared version range. Their versions describe the current linked manifests.
- Static source-origin evidence, with credentials, query strings, and fragments
  excluded from exported URLs and package identity. Local host paths are also
  excluded from URLs and identity.

Simple ALIRE version constraints are supported: `*`, exact versions, `=`, `/=`,
`>`, `>=`, `<`, `<=`, `^`, and `~`. ALIRE's caret keeps the same major version,
including for `0.x`. Compound version sets, conditional dependency tables,
external/provided crates, Git pins, pins inside dependency manifests, absolute
local pins, and overrides without an in-scope manifest are unsupported.
Local pins cannot follow symlinks or escape the scanned artifact. Individual
manifests and resolution files are limited to 10 MiB.

## Incomplete inventory

If resolution is missing, malformed, incomplete, unsupported, or observably
inconsistent with the manifests, Trivy emits an **Incomplete ALIRE inventory**
warning. It retains available root metadata and omits the dependency graph.
If the root manifest is unavailable or invalid, it emits no ALIRE application
for that lockfile. Version constraints are never emitted as resolved versions.
An empty project can be inventoried from its manifest alone.

Keep these warnings with the SBOM: the current output model does not embed the
warning as an inventory-completeness assertion. Root metadata alone must not be
interpreted as evidence that a project has no dependencies. Likewise,
`solution.context.solved=true` means solving was attempted; it can coexist with
unresolved states. Current manifests and resolution files do not prove which
inputs built a particular binary or that linked sources have remained unchanged.

## Package identity and re-import

The proposed identity uses `pkg:generic/alire/<name>@<version>` with an
`alire_source` qualifier. This is a Trivy inventory convention, **not an official
ALIRE PURL type or a crates.io identity**. The qualifier is a SHA-256 digest of
non-sensitive recorded source metadata, or the artifact-relative manifest
location for a root/local override. URL credentials, queries, fragments, and
local host paths are excluded before hashing. The qualifier is not a
source-content checksum or integrity guarantee, and sources that differ only in
excluded data can share an identity. Moving a local project can change its
identity. The resolution does not identify the supplying index, so
community/private index provenance cannot be established.

CycloneDX and SPDX JSON read/re-export preserve supported inventory and dependency
edges. The native JSON intermediate used by `trivy convert` also retains ALIRE
identities and dependency edges. Trivy's package relationship property preserves
root/direct/indirect roles in its own SBOMs; third-party SBOMs may omit it.
Only generic PURLs in the exact `alire` namespace are decoded as ALIRE.

## Vulnerability coverage

ALIRE vulnerability matching is not supported. Explicit vulnerability scans
retain the existing unsupported-ecosystem warning and do not create ALIRE
findings. An ALIRE package appearing in an SBOM, or a scan returning no ALIRE
findings, does not establish that the package has been checked against an
advisory source.
